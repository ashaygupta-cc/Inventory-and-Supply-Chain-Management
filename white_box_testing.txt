SECTION 1: INTRODUCTION TO WHITE BOX TESTING
================================================================================

White box testing (also called structural testing, glass-box testing, or
clear-box testing) is a software testing technique that examines the INTERNAL
logic, code paths, branches, loops, and data flows of an application — not
just its external behavior.

Unlike black-box testing (which only tests inputs vs. outputs), white box
testing requires the tester to have full knowledge of the source code.

KEY GOALS OF WHITE BOX TESTING:
- Achieve 100% statement coverage (every line of code is executed at least once)
- Achieve 100% branch coverage (every if/else branch is tested)
- Achieve 100% path coverage (every unique execution path is tested)
- Validate all exception/catch blocks are reachable and handled correctly
- Verify all loops execute correctly for 0, 1, and N iterations
- Confirm data transformations produce mathematically correct results
- Ensure security boundaries cannot be bypassed through internal logic

TYPES OF WHITE BOX TESTING USED IN THIS DOCUMENT:
1. Unit Testing       - Testing individual functions in isolation
2. Integration Testing - Testing how modules interact with each other
3. Control Flow Testing - Testing all branches and decision points
4. Data Flow Testing  - Tracking how data is created, used, and destroyed
5. Mutation Testing   - Verifying tests catch intentional code bugs
6. Boundary Value Analysis - Testing edge values at limits

3.1 INTERNAL LOGIC WALKTHROUGH
--------------------------------------------------------------------------------

FUNCTION: generateToken(userId: string): string
  Internal path:
    1. Calls jwt.sign({ userId }, JWT_SECRET, { expiresIn: "1h" })
    2. Returns signed token string
  Critical internal detail: JWT_SECRET defaults to "your_jwt_secret" if
  env variable is not set. This is a SECURITY RISK in production.

FUNCTION: verifyToken(token: string): { userId: string } | null
  Internal branches:
    Branch A: token is falsy, "null", or "undefined" -> return null
    Branch B: isServer is false (client-side) -> return null
    Branch C: jwt is undefined or jwt.verify missing -> return null
    Branch D: jwt.verify throws (expired/invalid) -> catch -> return null
    Branch E: jwt.verify succeeds -> return decoded payload

FUNCTION: getSessionFromRequest(request)
  Internal path:
    1. Extract cookie "session_id" from request
    2. If no cookie -> return null
    3. Call verifyToken(token)
    4. If verifyToken returns null -> return null
    5. Query prisma.user.findUnique({ where: { id: decoded.userId } })
    6. Return user (or null if not found in DB)

FUNCTION: hashPassword(password: string): Promise<string>
  Internal path:
    1. bcrypt.genSalt(10) -> generates salt with 10 rounds
    2. bcrypt.hash(password, salt) -> returns hashed string

FUNCTION: comparePassword(password, hashedPassword): Promise<boolean>
  Internal path:
    1. bcrypt.compare(password, hashedPassword) -> returns boolean

LOGIN ROUTE: POST /api/auth/login
  Internal decision tree:
    1. Parse request body -> if invalid object -> 400
    2. loginSchema.parse(body) -> if Zod fails -> throws ZodError -> 400
    3. prisma.user.findUnique({ where: { email } }) -> if null -> 401
    4. if !user.password -> 500 (corrupted data)
    5. bcrypt.compare(password, user.password) -> if false -> 401
    6. if !user.id -> 500 (corrupted data)
    7. generateToken(user.id) -> if null -> 500
    8. Set cookie "session_id" with token -> 200

--------------------------------------------------------------------------------
4.1 INTERNAL LOGIC WALKTHROUGH
--------------------------------------------------------------------------------

FUNCTION: generateOrderNumber(): Promise<string>
  Internal path:
    1. Get current date/time components
    2. Count orders created today (todayStart to todayEnd)
    3. sequence = todayOrders + 1, padded to 4 digits
    4. Return "ORD-{year}-{MMDD}-{HHMMSS}-{sequence}"
  Critical: sequence is based on count at time of call, NOT atomic.
  Race condition possible under high concurrency.

FUNCTION: createOrder(data, userId)
  Internal decision tree:
    1. generateOrderNumber() -> unique order number
    2. For each item in data.items:
       a. prisma.product.findUnique -> if null -> throw Error("Product not found")
       b. availableStock = product.quantity - product.reservedQuantity
       c. if availableStock < item.quantity -> throw Error("Insufficient stock")
       d. Calculate lineSubtotal = price * quantity
       e. Push to orderItemsData and productsToReserve
    3. Calculate total = subtotal + tax + shipping - discount
    4. prisma.order.create with items embedded
    5. For each product in productsToReserve:
       prisma.product.update -> reservedQuantity += qty
    6. Invalidate product cache (fire-and-forget, errors logged)
    7. Return created order

  STOCK RESERVATION LOGIC (CRITICAL):
    - On order CREATE (pending): reservedQuantity INCREASES (stock reserved)
    - On order CONFIRM/PAY: quantity DECREASES, reservedQuantity DECREASES
    - On order CANCEL: reservedQuantity DECREASES (reservation released)
    - availableStock = quantity - reservedQuantity (never goes negative)

5.1 INTERNAL LOGIC WALKTHROUGH
--------------------------------------------------------------------------------

FUNCTION: generateInvoiceNumber(): Promise<string>
  Internal path:
    1. Get current date: datePart = "YYYYMMDD", timePart = "HHMMSS"
    2. randomPart = Math.floor(1000 + Math.random() * 9000) -> 4-digit number
    3. invoiceNumber = "INV-{datePart}-{timePart}-{randomPart}"
    4. Check uniqueness: prisma.invoice.findUnique({ where: { invoiceNumber } })
    5. WHILE exists: generate new randomPart, check again
    6. Return unique invoiceNumber
  Critical: Uses random number, not sequential. Collision probability = 1/9000.
  The while loop handles collisions but could theoretically loop forever.

FUNCTION: createInvoice(data, userId)
  Internal decision tree:
    1. prisma.order.findUnique -> if null -> throw Error("Order not found")
    2. prisma.invoice.findUnique({ where: { orderId } }) -> if exists -> throw Error("Invoice already exists")
    3. generateInvoiceNumber() -> unique number
    4. Calculate amounts:
       subtotal = order.subtotal
       tax = data.tax ?? order.tax ?? 0
       shipping = data.shipping ?? order.shipping ?? 0
       discount = data.discount ?? order.discount ?? 0
       total = Math.max(0, subtotal + tax + shipping - discount)
    5. amountPaid = 0 (always starts at 0)
    6. amountDue = total
    7. billingAddress from order (JSON parse/stringify)
    8. prisma.invoice.create with status = "draft"

  CRITICAL FINANCIAL LOGIC:
    - total uses Math.max(0, ...) to prevent negative totals
    - amountDue starts equal to total (no payments yet)
    - tax/shipping/discount use nullish coalescing (??) not OR (||)
      This means 0 values from data are respected (not overridden by order values)

SECTION 6: MODULE 4 - DEMAND FORECASTING ENGINE
================================================================================

SOURCE FILES:
  - lib/forecasting/demand-forecast.ts

CONFIGURATION CONSTANTS (must be tested at boundaries):
  ANALYSIS_DAYS    = 30   (days of historical data)
  FORECAST_DAYS    = 14   (days to forecast ahead)
  ANOMALY_THRESHOLD = 2.0 (standard deviations for anomaly)
  REORDER_LEAD_DAYS = 7   (days lead time)

--------------------------------------------------------------------------------
6.1 INTERNAL LOGIC WALKTHROUGH
--------------------------------------------------------------------------------

FUNCTION: calculateMovingAverage(values, window)
  Internal path:
    For each index i:
      start = Math.max(0, i - window + 1)
      windowValues = values.slice(start, i + 1)
      avg = sum(windowValues) / windowValues.length
  Note: For early indices where i < window-1, uses partial window (not full window)

FUNCTION: calculateStdDev(values)
  Internal path:
    1. if values.length === 0 -> return 0
    2. mean = sum(values) / values.length
    3. squaredDiffs = values.map(v => (v - mean)^2)
    4. avgSquaredDiff = sum(squaredDiffs) / values.length
    5. return sqrt(avgSquaredDiff)
  Note: Uses POPULATION std dev (divides by N, not N-1)

FUNCTION: analyzeTrend(dailySales)
  Internal branches:
    Branch A: dailySales.length < 7 -> return { trend: "stable", percentageChange: 0 }
    Branch B: length >= 7 -> perform linear regression
      slope = (n*sumXY - sumX*sumY) / (n*sumXX - sumX*sumX)
      percentageChange = avgY > 0 ? (slope * n * 100) / avgY : 0
      Branch B1: percentageChange > 10  -> trend = "increasing"
      Branch B2: percentageChange < -10 -> trend = "decreasing"
      Branch B3: else                   -> trend = "stable"

FUNCTION: detectAnomalies(productId, productName, sku, dailySales)
  Internal branches:
    Branch A: dailySales.length < 7 -> return [] (no anomalies)
    Branch B: stdDev === 0 -> return [] (all values identical, no anomalies)
    Branch C: For each day, zScore = |day.quantity - mean| / stdDev
      if zScore > ANOMALY_THRESHOLD (2.0):
        Branch C1: zScore > 3    -> severity = "high"
        Branch C2: zScore > 2.5  -> severity = "medium"
        Branch C3: else (> 2.0)  -> severity = "low"
        Branch C4: day.quantity > mean -> anomalyType = "spike"
        Branch C5: day.quantity < mean -> anomalyType = "drop"

FUNCTION: generateProductForecast(...)
  Internal path:
    1. availableStock = currentStock - reservedStock
    2. averageDailySales = sum(quantities) / quantities.length (or 0 if empty)
    3. recentDays = dailySales.slice(-7) (last 7 days)
    4. recentAvg = sum(recentDays) / recentDays.length (or 0 if empty)
    5. predictedDailySales:
       if recentDays.length >= 7: recentAvg * 0.7 + averageDailySales * 0.3
       else: averageDailySales
    6. daysUntilStockout:
       if predictedDailySales > 0: floor(availableStock / predictedDailySales)
       else: null
    7. reorderRecommendation:
       if daysUntilStockout <= 7:  "urgent"
       if daysUntilStockout <= 14: "soon"

IDENTIFIER RESOLUTION (standard/strict):
  1. Check x-user-id header -> if present: "user:{userId}"
  2. Else check x-real-ip -> "ip:{ip}"
  3. Else check x-forwarded-for -> "ip:{ip}"
  4. Else: "ip:unknown"

IDENTIFIER RESOLUTION (auth):
  Always uses IP (ignores user ID) to prevent brute force per-account

FUNCTION: withRateLimit(request, config, overrideIdentifier?)
  Internal path:
    1. Get identifier (overrideIdentifier OR config.getIdentifier(request))
    2. checkRateLimit(identifier, config.limit, config.window)
    3. If rate limited: return 429 response with Retry-After header
    4. If not limited: return null (allow request to proceed)

  import { describe, it, expect } from 'vitest'
  import jwt from 'jsonwebtoken'
  import { verifyToken } from '@/utils/auth'

  describe('verifyToken', () => {
    it('AUTH-005: returns null for expired token', async () => {
      // Generate a token that expires in 1ms
      const expiredToken = jwt.sign(
        { userId: 'test-user' },
        process.env.JWT_SECRET || 'your_jwt_secret',
        { expiresIn: '1ms' }
      )

      // Wait for token to expire
      await new Promise(resolve => setTimeout(resolve, 10))

      const result = verifyToken(expiredToken)
      expect(result).toBeNull()
    })

    it('AUTH-004: returns userId for valid token', () => {
      const token = jwt.sign(
        { userId: 'user123' },
        process.env.JWT_SECRET || 'your_jwt_secret',
        { expiresIn: '1h' }
      )

      const result = verifyToken(token)
      expect(result).toEqual({ userId: 'user123' })
    })

    it('AUTH-001: returns null for empty string', () => {
      expect(verifyToken('')).toBeNull()
    })

    it('AUTH-002: returns null for string "null"', () => {
      expect(verifyToken('null')).toBeNull()
    })
  })
